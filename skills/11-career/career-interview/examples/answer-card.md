# 예시: 답변 카드

출처 성과 문장: "주문 목록 조회에 Redis 캐시 계층을 도입해 p95를 820ms에서 140ms로 줄임"

### Q. 캐시를 붙이면 데이터 일관성 문제는 없었나요?

- **결론:** 주문 목록은 몇 초 늦어도 되는 데이터라 TTL 30초 + 주문 상태 변경 시 해당 키 삭제로 처리했습니다.
- **근거:** 결제 상태처럼 즉시성이 필요한 필드는 캐시에서 빼고 항상 DB에서 읽었습니다. 도입 후 3개월 동안 불일치 문의는 0건이었습니다.
- **꼬리 1:** 키 삭제와 DB 쓰기 순서는요? → DB 커밋 후 삭제, 삭제 실패는 TTL이 보완
- **꼬리 2:** 캐시가 한꺼번에 만료되면요? → TTL에 무작위 지터, 인기 키는 미리 갱신

말하기 분량: 약 250자, 40초.

## 모의 모드 피드백 예

| 항목 | 평가 | 메모 |
|------|------|------|
| 결론 위치 | 좋음 | 첫 문장에 전략 |
| 구체성 | 좋음 | TTL, 0건 |
| 길이 | 보통 | 꼬리 질문 대비해 첫 답은 더 짧아도 됨 |
| 위험 | 낮음 | "3개월 0건" 근거 질문 대비 필요 |
