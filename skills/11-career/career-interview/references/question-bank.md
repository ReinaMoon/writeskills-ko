# 면접 질문 은행

## 공통 (거의 항상)

1. 1분 자기소개
2. 지원 동기
3. 이직(퇴사) 사유
4. 가장 자신 있는 프로젝트
5. 실패하거나 아쉬웠던 프로젝트
6. 동료와 의견이 달랐던 경험
7. 입사하면 처음 3개월 동안 할 일
8. 마지막으로 질문 있나요

## 서류 기반 꼬리 질문 생성 규칙

성과 문장 하나마다:

| 각도 | 질문 틀 |
|------|---------|
| 방법 | 구체적으로 어떻게 했나요? |
| 선택 | 다른 방법은 왜 안 썼나요? |
| 측정 | 그 수치는 어떻게 쟀나요? |
| 역할 | 본인이 한 부분은 어디까지인가요? |
| 회고 | 다시 한다면 무엇을 바꾸나요? |
| 확장 | 트래픽이 10배면 어떻게 되나요? |

## 기술 면접 (백엔드 예)

| 영역 | 질문 예 |
|------|---------|
| DB | 인덱스가 안 타는 경우, 트랜잭션 격리 수준 차이 |
| 캐시 | 캐시 일관성 전략, 캐시 스탬피드 |
| 네트워크 | 브라우저 주소 입력 후 일어나는 일 |
| 운영 | 장애를 처음 인지했을 때 하는 순서 |
| 설계 | URL 단축기, 알림 시스템 설계 |

다른 직군(프론트엔드, 데이터, SRE, PM)은 공고 키워드로 같은 표를 만든다.

## 약점 질문 답변 틀

| 질문 | 틀 |
|------|----|
| 공백기 | 기간 사실 + 그동안 한 일 + 지금 준비 상태 |
| 짧은 재직 | 이유 사실 1문장 + 배운 점 + 이번엔 왜 다른지 |
| 연봉 | 현재 수준 + 희망 범위 + 조율 가능성 |
| 단점 | 실제 단점 + 보완 행동 + 결과 |

## 역질문 후보

- 이 포지션이 입사 후 6개월 안에 해결하길 기대하는 문제는 무엇인가요?
- 팀의 배포 주기와 온콜 방식은 어떤가요?
- 최근 팀에서 가장 크게 바뀐 기술 결정은 무엇이었나요?
