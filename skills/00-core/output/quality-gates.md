# 공통 품질 게이트

완성 조건과 점검 영역입니다. 스킬별 체크리스트는 이 골격을 확장합니다.

---

## 1. 게이트 종류

| 게이트 | 시점 | 통과 조건 |
|--------|------|-----------|
| G0 입력 | Step 1 진입 전 | 목적, 독자, 장르(또는 문서 유형)가 확인됨 |
| G1 구조 | 초안 전 | 아웃라인/슬롯이 사용자 확인됨 |
| G2 초안 | 퇴고 전 | 필수 슬롯이 비어 있지 않음 (`[미정]` 허용 범위는 스킬 정의) |
| G3 문장 | 최종 전 | `writing-principles` 금지어, 어미 통일, `ai-tone-patterns` 밀도 1.0 미만 |
| G4 형식 | 최종 전 | `output-rules` 파일명, 포맷 준수 |
| G5 인계 | 다음 스킬 전 | `handoff-schema` 필수 슬롯 채워짐 또는 `[미정]` 명시 |

사용자가 “건너뛰고 초안”을 요청하면 G1을 약식으로 통과시킬 수 있으나, 최종 전에 G1~G3을 소급 점검합니다.

---

## 2. 공통 점검 4영역

| 영역 | 볼 것 | 실패 시 |
|------|-------|---------|
| 구조 | 장르/유형 골격, 중복 섹션, 도입, 마무리 | 재배치, 삭제, 도입 교체 |
| 문장 | 길이, 어미, 단정, 금지어 | 분리, 치환, 단정화 |
| 스타일 | mystyle/tone-matrix 이탈 | 리듬, 어휘, 엔딩 교정 |
| 형식 | 분량, 제목, 출처, CTA/액션 필드 | 유형 기준에 맞게 조정 |

판정 표는 `output-rules.md` 포맷을 씁니다.

## 3. 장르별 최소 완성 조건

### 글쓰기 (content/blog/essay/social)
- [ ] 목적, 독자가 본문에 반영됨
- [ ] 유형 구조 이탈 없음
- [ ] 금지어 자가 질문 통과
- [ ] 제목 확정 (또는 후보 합의)

### 책, 강의 체인
- [ ] 인계 블록 또는 기획서가 후속 입력으로 충분함
- [ ] 챕터/꼭지 번호 체계 유지
- [ ] 출처 필요 지점에 등급 또는 TODO

### 조사, 사업계획
- [ ] 주장과 근거의 짝이 맞음
- [ ] A급 출처가 필요한 핵심 수치에 존재 (없으면 명시적 공백)
- [ ] missing 슬롯 목록이 남아 있으면 보고서에 노출

### 위키
- [ ] `type`, `sources`, `updated` (또는 폴더 대체 스키마) 존재
- [ ] concept/experience 혼입 없음
- [ ] 페이지명 규약 준수

### IT 실무
- [ ] 결정, 액션에 오너, 기한이 있거나 `TBD`로 명시
- [ ] 런북은 전제, 절차, 검증, 롤백이 구분됨
- [ ] 회의록은 결정과 액션이 메모 나열과 분리됨

### 소설 모드 (book-editing 공유)
체크리스트 본문: `skills/02-book/book-editing/references/novel-mode.md`
- [ ] `style-guide.md`(또는 설계 키트) 대비 보이스 위반 없음
- [ ] 시점, 시제, 어미 일관성
- [ ] Show/don't tell, 대사 개성, 설명문 덤프 점검 (편집 패스)
- [ ] 별도 novel-editing 스킬 없이 `book-editing` 소설 모드로 종료

### 이미지 프롬프트 (`09-image`)
- [ ] 모드(표지/삽화 또는 썸네일/인포)와 비율이 확정됨
- [ ] 프롬프트가 벤더 중립 블록/섹션으로 구조화됨
- [ ] 표시 텍스트와 디자인 사양(렌더 금지 스펙)이 분리됨
- [ ] 시리즈면 스타일, 팔레트, 캐릭터 규약이 고정됨
- [ ] 바이너리 이미지는 선택 런타임(필수로 강제하지 않음)

## 4. IT 실무 통과/실패 예시 (`doc-meeting`)

| 영역 | 통과 | 실패 |
|------|------|------|
| 구조 | 개요 / 결정 / 액션 / 논의메모가 분리됨 | 전사 문장을 시간순으로만 붙여 둠 |
| 문장 | 명사형, 단정. 잡담 없음 | “유익한 논의였다” 등 감상형 |
| 형식 | 액션에 담당, 기한 또는 `TBD` | 담당만 있고 기한 없음(표시도 없음) |
| 사실 | 입력에 있는 결정만 기록 | 참석하지 않은 합의를 채워 넣음 |

## 5. 실패 처리

1. 판정 `수정 필요` 항목만 고친다 (L2/L3 범위 준수).
2. 구조 실패와 문장 실패가 동시에 있으면 구조를 먼저 고친다.
3. 출처 공백은 문장을 미화하지 말고 마커를 남긴다.
4. 게이트를 통과시키지 못한 채 다음 스킬로 넘기지 않는다. 예외 시 인계 문서에 `risk:`로 기록한다.
