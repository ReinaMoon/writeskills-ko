# 공통 출력 규칙

다단계 스킬의 **산출물 형식, 파일명, 확인 게이트** 공통 규약입니다. 
스킬별 Step 이름, 슬롯은 각 `SKILL.md`가 정의하고, 이 파일은 형식만 고정합니다.

docx/pptx 생성은 본 규칙의 기본이 아닙니다. 필요 시 `adapters/runtime-files.md`를 따릅니다.

---

## 1. 기본 원칙

1. **단계마다 산출물을 명시**한다. 대화창 텍스트만으로 끝나는 단계도 “산출물 = 대화 요약”으로 적는다.
2. **사용자 확인 후 다음 Step**이 기본이다. 사용자가 “한 번에”를 요청하면 게이트를 묶을 수 있다.
3. **마크다운이 기본 산출**이다. 바이너리 포맷은 선택 어댑터.
4. 파일명은 ASCII, 한글 모두 허용하되, 체인 안에서는 **패턴을 고정**한다.
5. 임시 초안과 최종본 파일명을 섞지 않는다 (`draft` / `final` 구분).

---

## 2. 단계 유형별 산출물

| 단계 유형 | 기본 형식 | 선택 형식 | 확인 |
|-----------|-----------|-----------|------|
| 목적, 범위 정의 | 대화 요약 (항목 리스트) | (없음) | 필수 |
| 아웃라인, 목차 | 대화 MD | `outline.md` | 필수 |
| 초안 | 대화 MD | `draft.md` | 필수 |
| 점검, 퇴고 | 점검 표 + 수정본 | (없음) | 필수 |
| 최종본 | `final.md` | docx/html/pptx (어댑터) | 필수 |
| 인계 블록 | 고정 슬롯 MD | YAML frontmatter | 다음 스킬 입력 |
| 참조 카드 | 카드 스키마 MD | JSON (biz 프로필) | 집필 전 |

---

## 3. 파일명 패턴

프로젝트 루트 또는 체인 폴더 기준.

| 산출 | 패턴 | 예 |
|------|------|----|
| 기획 인계 | `00-handoff.md` | |
| 아웃라인 | `outline.md` | |
| 초안 | `draft.md` / `draft-ch{NN}.md` | `draft-ch03.md` |
| 최종 | `final.md` / `{slug}-final.md` | |
| 참조 카드 | `RL-{slug}.md` 또는 `ref-ch{NN}.md` | |
| 사업계획 입력 | `bizplan_input_{name}_{YYMMDD}.json` | |
| 위키 페이지 | 제목 = 파일명 | `MCP.md` |
| 회의/주간 | `{type}-{YYYY-MM-DD}.md` | `meeting-2026-11-10.md` |
| 이미지 프롬프트(책) | `IB_{slug}_{YYYYMMDD}.md` | `IB_mybook_261110.md` |
| 이미지 프롬프트(콘텐츠) | `IC_{slug}_{YYYYMMDD}.md` | `IC_post-seo_261110.md` |
| 이미지 스타일 바이블 | `style-bible.md` | 표지, 삽화 시리즈 공통 |

규칙:

- 챕터, 꼭지 번호는 **2자리** (`01`, `02`).
- 날짜는 `YYYY-MM-DD` 또는 파일명 압축 `YYMMDD`.
- 버전을 남길 때 `_v2` 접미사. 덮어쓰기 전 사용자 확인.

---

## 4. 점검 리포트 포맷

퇴고, 리뷰 Step에서 표를 씁니다.

```markdown
| # | 영역 | 항목 | 판정 | 수정 방향 |
|---|------|------|------|----------|
| 1 | 구조 | … | O / 수정 필요 | … |
```

변경 요약 (수정본 하단):

```markdown
**주요 변경 사항:**
- 구조: …
- 문장: …
- 스타일: …
- 형식/채널: …
```

영역 정의는 `quality-gates.md`를 따릅니다.

---

## 5. 제목, 메타

- 최종본 제목은 후보 **3~5개**를 제시한 뒤 사용자 선택을 받는다 (사용자가 제목을 이미 정했으면 생략).
- MD frontmatter를 쓸 때 최소 필드:

```yaml
---
title: ""
date: YYYY-MM-DD
status: draft | review | final
skill: "{skill-name}"
---
```

---

## 6. 스킬 작성자 체크

새 스킬의 출력 절을 쓸 때:

- [ ] Step마다 산출물, 형식이 표로 있는가
- [ ] 기본이 MD인가 (바이너리는 어댑터로 분리했는가)
- [ ] 인계가 필요하면 `handoff-schema.md` 슬롯을 재사용하는가
- [ ] 드롭된 채널, 양식 파일명을 가리키지 않는가
