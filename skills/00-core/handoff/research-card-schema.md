# 참조 카드 스키마

책, 강의, 사업계획, 일반 조사가 공유하는 카드 필드입니다. 
스킬별로 템플릿 파일을 복제하지 말고, 이 스키마의 프로필을 고릅니다.

---

## 1. 출처 등급 (공통)

| 등급 | 의미 | 예 | 사용 |
|------|------|----|------|
| A | 1차, 공공, 동료심사, 공식 통계 | 정부 통계, 표준 문서, 학술지 | 핵심 수치에 우선 |
| B | 신뢰 가능한 2차 | 업계 리포트, 협회, 정식 조사기관 | A 없을 때 대체 |
| C | 보조 | 언론, 블로그, IR, 소셜 | 단독 근거 금지 |

표기: `(출처: 기관, 연도, 등급: A/B/C, 조사일: YYYY-MM-DD)`

---

## 2. 책 챕터 카드 (`profile: book`)

### A 모드: 집필 전

```markdown
# Ch{NN} 참조 자료 팩

## 챕터 정보
- 챕터 제목:
- 리서치 방향:
- 관점 연결: (없으면 생략)

## ① 핵심 팩트
1. …: 근거
2. …
3. …

## ② 인용 가능 수치
- 수치: 기관, 연도, URL, 등급 (조사일)

## ③ 사례, 레퍼런스
### {제목}
- 요약:
- 출처: (등급)
- 집필 활용:

## ④ 반론, 주의점
- 오해/한계 → 대응

## ⑤ 관련 키워드
키워드1, 키워드2, …
```

분량 가이드: 약 1,000~1,200자.

### B 모드: 초안 이후 검증

A 모드 필드 + 

- 사례에 **원고 인용 위치**, **검증 결과**(일치/불일치)
- ⑥ 보강, 수정 제안 (원고에 반영할 구체 문장/수치)

분량 가이드: 약 1,500~2,200자. 
원고 파일 유무로 모드 자동 판별. 사용자 지정이 있으면 우선.

## 3. 강의 꼭지 카드 (`profile: lecture`)

꼭지마다 아래 슬롯을 채웁니다. 비해당은 `N/A`.

| 슬롯 | 이름 | 요지 |
|-----:|------|------|
| 1 | 도입 훅 | 주의 환기 + 슬롯2 연결 1줄 |
| 2 | 핵심 개념 | 정의, 오해 |
| 3 | 데이터 포인트 | 수치+등급, 차트화 가능 표시 |
| 4 | 대표 사례 | 3개까지, 요약+출처+메시지 |
| 5 | 본인 사례 | 상황, 한 일, 결과 |
| 6 | 비교 매트릭스 | 해당 시 |
| 7 | 반박과 응답 | 예상 반론 |
| 8 | 실습 소재 | 시간, 재료, 검증 메시지 |
| 9 | 수준별 설명 | 초/중/고 |
| 10 | 시각 소재 | 이미지, 도식, 차트 ID |
| 11 | 구술 멘트 | 도입/전환/마무리 |
| 12 | 꼭지 내부 흐름 | 단계별 사용 슬롯 |

시각 소재(ID): `I#` 이미지, `G#` 도식, `C#` 차트.

## 4. 사업계획 카드 (`profile: biz`)

정부 양식 번호에 묶지 않습니다. 일반 BP용 5종 + 집필 입력 객체.

### 5종 카드

| 코드 | 이름 | 핵심 필드 |
|------|------|-----------|
| P | Problem & Market | TAM/SAM/SOM, 고객 통계, 정책, 문제 사례 |
| R | Reference | 유사, 경쟁, 벤치마크 사례 |
| S | Solution & Model | 제안, 기능, KPI, 가격, 채널 |
| C | Competition | 비교표, 차별점+근거, 모방 난이도 |
| U | Us (팀, 실적) | 이력, 역량 매핑, 협력망 |

공통 헤더:

```markdown
# BR_{P|R|S|C|U}-카드_{사업명}_{YYMMDD}

- 사업 아이템: (한 줄)
- 타깃 고객:
- 업종:
- 작성일:
- 주요 출처 등급:
```

### 집필 입력 객체 (bizplan-write용)

JSON 또는 MD 섹션. K-Startup 소항목 번호 대신 **일반 절 키**를 씁니다.

```json
{
 "meta": {
 "name": "",
 "one_liner": "",
 "date": "YYYY-MM-DD",
 "industry": "",
 "purpose": "investor | internal",
 "keywords": []
 },
 "sections": {
 "problem": {},
 "solution": {},
 "market": {},
 "business_model": {},
 "gtm_growth": {},
 "competition": {},
 "team": {},
 "financials": {},
 "milestones": {}
 },
 "tables": {},
 "source_grades": {},
 "missing": []
}
```

각 section 값은 카드에서 온 필드, 표 참조, 출처 등급을 포함합니다. 
`missing`에 빈 절을 남겨 write 단계가 질문할 수 있게 합니다.

파일명: `bizplan_input_{name}_{YYMMDD}.json`

## 5. 일반 조사 노트 (`profile: topic`)

`research-topic` 기본/딥/배치 공통 최소 필드.

```markdown
# RL_{주제}

## 질문
## 요약 (5줄 이내)
## 핵심 발견
## 수치, 인용
## 반론, 불확실성
## 출처 목록 (등급)
## 다음 조사
```

배치 모드: 마스터 노트 1 + 서브 `RL_{주제}_{nn}.md`. 마스터에 인덱스 표를 둡니다.

---

## 6. 공통 검증

- [ ] 핵심 수치에 등급 표기
- [ ] C급만으로 핵심 주장 지지하지 않음
- [ ] 카드 ID/챕터 번호가 인계 목차와 일치
- [ ] `missing` / `[미정]`이 숨겨지지 않음
