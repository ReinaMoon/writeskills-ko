# 런타임 파일 어댑터

**무엇을 쓸지(스펙)** 와 **어떤 바이너리로 만들지(런타임)** 를 분리합니다. 
스킬 본문은 MD 스펙, 체크리스트만 정의하고, 파일 생성은 이 어댑터를 **선택적으로** 따릅니다.

---

## 1. 기본값

| 산출 | 기본 | 선택 런타임 |
|------|------|-------------|
| 글, 보고서, 인계 | `.md` | docx, html |
| 슬라이드 | 슬라이드 스펙 `.md` | pptx |
| 사업계획 입력 | `.json` / `.md` | (없음) |
| 이미지 | 프롬프트 `.md` | 이미지 생성 도구 |

런타임이 없으면 MD만으로 체인을 완료할 수 있어야 합니다.

---

## 2. 호출 원칙

1. 사용자가 바이너리를 **명시적으로** 요청하거나, 스킬이 “선택: docx”로 안내한 경우에만 생성한다.
2. 생성 전 해당 환경의 문서 스킬/라이브러리 지침을 읽는다 (경로, API는 환경마다 다름).
3. 스킬 MD에 특정 제품의 하드코딩 경로(`/mnt/skills/...` 등)를 남기지 않는다. “환경 문서 스킬을 따른다”고만 적는다.
4. 실패 시 MD 파일은 보존하고, 바이너리 실패만 보고한다.

---

## 3. 슬라이드

- `lecture-slides`의 기준 문서는 **장별 메시지 스펙 MD**.
- pptx 빌더는 어댑터: 스펙 > 슬라이드 객체 > 파일.
- 리뷰(`lecture-review`)는 스펙 기준으로 먼저 통과시키고, pptx는 부가 확인.

---

## 4. 보고서 docx

- `research-report`는 MD 절 구조가 기본.
- docx 템플릿/스크립트는 배포물에만 포함하고, 코어에는 넣지 않는다.

---

## 5. 스크립트, 도구

- Python/JS 빌더, 이미지 CLI 등은 `adapters` 또는 스킬 `scripts/`에 둔다.
- 코어 모듈에는 코드 본문을 두지 않고, “스펙 필드 ↔ 스크립트 입력” 매핑만 스킬에 적는다.
