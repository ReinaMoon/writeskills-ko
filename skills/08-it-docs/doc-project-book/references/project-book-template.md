# 프로젝트북 섹션 가이드

`doc-project-book`에서 사용한다.

## 절별 채우기 요령

| 절 | 넣을 것 | 넣지 말 것 |
|----|---------|------------|
| 1 목적 | 문제, 성공 지표 1~3개 | 비전 슬로건만 |
| 2 범위 | In/Out 불릿 | 모호한 "등" |
| 3 역할 | 이름, 역할, 연락 채널 | 전 회사 조직도 |
| 4 인터페이스 | 시스템 경계, 주요 API/이벤트 | 전체 OpenAPI 덤프 (링크) |
| 5 결정 로그 | 날짜, 결정, 근거, 상태 | 회의 잡담 |
| 6 리스크 | 영향, 완화, 오너 | 막연한 불안 |
| 7 일정 | 마일스톤 날짜 | 시간 단위 간트 전체 |
| 8 운영 | 런북, 온콜, 대시보드 링크 | 절차 본문 복붙 |
| 9 커뮤니케이션 | 채널, 회의 주기 | 모든 슬랙 히스토리 |
| 10 부록 | 용어, 환경 이름 | 비밀번호 |

## 결정 로그 상태값

- `채택`: 현재 유효
- `대체됨`: 새 결정 ID/날짜 링크
- `폐기`: 더 이상 유효하지 않음
- `제안`: 아직 미확정 (본문 단정에 쓰지 않음)

## update 모드 상단 요약

```markdown
> 갱신 ({YYYY-MM-DD}): §5 결정 2건 추가, §7 마일스톤 날짜 수정
```
