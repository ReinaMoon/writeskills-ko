# 예시: 배포 런북 (실패 분기 포함)

```markdown
# 런북: 결제 API 카나리 배포

## 범위
- 다룸: `payments-api` 카나리 10% → 100%
- 다루지 않음: DB 마이그레이션 (별도 런북)

## 전제, 권한
- VPN, `kubectl` prod, Slack `#ops`
- 유지보수 창: 화 01:00–03:00 KST
- 담당: oncall-a

## 절차
1. 헬스체크 기준선 기록 (`/health` 200, p99 < 300ms)
2. 이미지 태그 배포 (카나리 10%)
3. 15분 관찰: 에러율 < 1%
4. 문제 없으면 100%로 승격

## 검증
- `/health` 200
- 결제 성공률 대시보드 15분 창에서 전일 대비 ±0.5%p 이내

## 실패 분기, 롤백
| 증상 | 위치 | 조치 |
|------|------|------|
| 에러율 ≥ 1% | 절차 3 | 카나리 0%로 롤백 후 `#ops` 공지 |
| 헬스 실패 | 절차 2 직후 | 배포 중단, 이전 ReplicaSet으로 롤백 |
| 롤백 후에도 실패 | 롤백 후 | 에스컬레이션: secondary oncall |

## 온콜
- 1차: oncall-a / 2차: oncall-b
- 상태 페이지: status.example.com (외부 공지 필요 시)
```
