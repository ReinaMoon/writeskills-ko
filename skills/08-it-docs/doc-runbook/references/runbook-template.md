# 런북 작성 가이드

`doc-runbook` Step 1~7에서 사용한다.

## 단계 작성 패턴

좋은 단계:

```markdown
3. 배포 파이프라인 `deploy-pay-api`를 prod에 실행한다
 - 명령: `…` (또는 UI 경로)
 - 기대 결과: 파이프라인 성공, 버전 태그 `vX.Y.Z` 표시
```

나쁜 단계:

- "배포를 적절히 수행한다"
- "문제 없으면 다음으로"

## 검증 신호 예시 유형

| 유형 | 예 |
|------|-----|
| 헬스 | `/health` 200, ready true |
| 메트릭 | 에러율 < 1%, p99 < N ms |
| 로그 | 특정 ERROR 코드 부재 |
| 합성 | 스모크 테스트 스위트 통과 |

입력에 수치가 없으면 신호 이름만 적고 임계값은 `TBD`.

## 롤백 최소 요건

1. 트리거(언제 롤백하나)
2. 명령/클릭 경로
3. 롤백 후 검증
4. 데이터 마이그레이션 등 비가역 항목

## 심각도 (선택 표기)

팀 표준이 있으면 그것을 쓴다. 없으면:

| SEV | 예 |
|-----|-----|
| 1 | 전면 장애, 매출/안전 직결 |
| 2 | 주요 기능 저하 |
| 3 | 부분 영향, 우회 가능 |
| 4 | 낮은 영향, 업무 시간 처리 |
