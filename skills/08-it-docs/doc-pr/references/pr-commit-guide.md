# PR, 커밋, 리뷰 코멘트 가이드

## PR 제목

| 약함 | 강함 |
|------|------|
| 버그 수정 | 주문 취소 시 쿠폰이 복구되지 않던 문제 수정 |
| 리팩터링 | 결제 모듈 외부 API 호출을 어댑터로 분리 |
| 기능 추가 | 관리자 주문 목록에 결제 수단 필터 추가 |

## conventional commits

```
<type>(<scope>): <요약>

<본문: 왜 바꿨는지, 이전 동작과 차이>

<꼬리: Refs #123, BREAKING CHANGE: ...>
```

| type | 쓰는 때 |
|------|---------|
| feat | 사용자에게 보이는 기능 |
| fix | 버그 수정 |
| refactor | 동작 변화 없는 구조 변경 |
| perf | 성능 |
| test | 테스트만 |
| docs | 문서만 |
| chore | 빌드, 의존성, 설정 |
| ci | 파이프라인 |

팀이 국문 요약을 쓰면 type만 영문, 요약은 국문으로 통일.

## 리뷰 코멘트 라벨

| 라벨 | 의미 | 예 |
|------|------|----|
| [필수] | 머지 전 고쳐야 함 | [필수] 트랜잭션 밖에서 상태를 바꾸면 중복 결제 가능성이 있습니다. 서비스 메서드 안으로 옮기면 어떨까요? |
| [제안] | 더 나은 방법 | [제안] 이 분기는 early return으로 쓰면 들여쓰기가 줄어듭니다. |
| [질문] | 의도 확인 | [질문] 타임아웃 3초는 상대 API SLA 기준인가요? |
| [사소] | 취향, 오타 | [사소] 변수명 오타 recieve → receive |

## 코멘트 다듬기

| 거친 원문 | 다듬은 문장 |
|-----------|-------------|
| 이거 왜 이렇게 짰어요? | [질문] 여기서 리스트를 두 번 순회하는 이유가 있을까요? 한 번에 합칠 수 있어 보입니다. |
| 테스트 없네요 | [필수] 쿠폰 복구 분기 테스트가 있으면 회귀를 막을 수 있습니다. 취소 + 쿠폰 사용 케이스 하나 추가 부탁드립니다. |
