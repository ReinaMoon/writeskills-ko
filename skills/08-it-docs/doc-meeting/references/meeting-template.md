# 회의록 템플릿, 분류 가이드

`doc-meeting` Step 2~4에서 사용한다.

## 분류 기준

| 유형 | 판별 | 넣는 곳 |
|------|------|---------|
| 결정 | "하기로 했다", "확정", "채택", 반대 의견 없이 합의 | §2 결정사항 |
| 액션 | 누가 / 무엇을 / 언제까지가 언급되거나 암시됨 | §3 표 |
| 논의 메모 | 의견만 오고 감, 보류, 추가 조사 필요 | §4 |
| 잡담, 중복 | 실행과 무관 | 삭제 |

애매하면 결정으로 올리지 말고 §4에 두고, 질문으로 확인한다.

## 액션 행 규칙

- 담당: 사람 이름 또는 역할. 팀명만 있으면 팀명 + `TBD(담당)`.
- 할 일: 동사로 시작하는 한 줄 (`○○ 배포 일정 확정`).
- 기한: `YYYY-MM-DD` 또는 상대 표현이 입력에 있으면 그대로. 없으면 `TBD`.
- 한 행 = 한 실행 단위. "A하고 B한다"는 두 행으로 쪼갠다.

## 최소 예시 (구조만)

```markdown
# 2026-11-10 API 장애 회고 회의록

## 1. 회의 개요
- 일시: 2026-11-10 14:00-14:40 KST
- 참석: 김○(온콜), 이○(백엔드), 박○(SRE)
- 안건: 원인 공유, 재발 방지, 런북 보강

## 2. 결정사항
- 타임아웃 기본값을 3초 → 5초로 변경한다
- 장애 알림 채널을 `#ops-alert`로 단일화한다

## 3. 액션아이템
| 담당 | 할 일 | 기한 |
|------|-------|------|
| 이○ | 타임아웃 설정 PR | 2026-11-12 |
| 박○ | 런북 롤백 절 보강 | TBD |

## 4. 논의 메모
- 서킷브레이커 도입은 다음 스프린트 백로그에서 재논의
```
