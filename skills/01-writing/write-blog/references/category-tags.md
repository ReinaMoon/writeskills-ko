# 블로그 카테고리, 태그 (IT / 소프트웨어 개발)

소프트웨어 개발자, 플랫폼/인프라 엔지니어, 테크리드가 기술 블로그를 운영할 때 쓰는 **기본 분류**다.  
특정 개인 블로그 체계가 아니다. 팀/개인 저장소에 이미 분류가 있으면 그 이름을 우선하고, 없을 때만 아래를 쓴다.

## 1. 카테고리

| 카테고리 | 설명 | 대표 주제 |
|----------|------|-----------|
| 백엔드 | 서버, API, 데이터 계층 | REST/gRPC, DB, 캐시, 메시지큐 |
| 프론트엔드 | 웹/앱 UI, 클라이언트 | React/Vue, 성능, 접근성, 상태관리 |
| 인프라, 클라우드 | 배포, 운영, 플랫폼 | Kubernetes, Terraform, CI/CD, 관측 |
| 아키텍처 | 설계 판단, 트레이드오프 | 도메인 경계, 이벤트, 확장성, 장애 격리 |
| 품질, 테스트 | 검증, 안정성 | 단위/통합, 계약 테스트, 카오스, 성능 |
| 보안 | 위협, 인증, 시크릿 | OAuth, 권한, 공급망, 취약점 대응 |
| 데이터, ML | 파이프라인, 모델 서빙 | ETL, feature store, 온라인 추론 |
| 엔지니어링 실무 | 협업, 문서, 온보딩 | 코드리뷰, 런북, RFC, 장애 회고 |
| 도구, 워크플로 | 로컬/팀 생산성 도구 | IDE, lint, 자동화, LLM 보조 |

글 1개당 카테고리 **1~2개**. 3개 이상 붙이지 않는다.  
겹치면 **핵심 판단이 속한 쪽**만 고른다. 예: “K8s에서 롤백 설계” → 인프라 (+선택 아키텍처).

## 2. 태그 규칙

- 글당 **2~4개**
- 유형: 스택명 / 기법 / 주제 키워드 / 포맷(가이드, 회고, 비교, 체크리스트)
- 표기 통일: `Kubernetes`와 `쿠버네티스` 혼용 금지. 문서 첫 등장 표기를 고정
- 새 태그는 앞으로 3편 이상 쓸 때만 추가
- 붙여쓰기 기본: `카나리배포`, `장애회고`, `코드리뷰`

## 3. 자주 쓰는 태그 예시

### 스택, 플랫폼
Kubernetes, Docker, PostgreSQL, Redis, Kafka, AWS, GCP, Terraform, GitHubActions

### 기법, 주제
API설계, 관측성, 카나리배포, 롤백, 장애회고, 온보딩, RFC, 런북, 성능튜닝, 인증인가

### 포맷
가이드, 체크리스트, 회고, 비교, 딥다이브
