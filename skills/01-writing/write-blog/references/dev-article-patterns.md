# 기술 블로그 코드글 패턴

`write-blog`에서 글 유형이 코드/실무 구현일 때 사용.

## 유형

| 코드 | 이름 | 핵심 |
|------|------|------|
| BUG | Bug Hunt | 증상 → 원인 → 수정 → 재발 방지 |
| BUILD | How we built | 제약 → 선택 → 구현 → 트레이드오프 |
| BENCH | Benchmark | 가설 → 방법 → 수치 → 한계 |
| MIG | Migration | before → after → 롤백 → 체크리스트 |
| LESSON | Lessons | 사건 → 배움 → 다음에 할 일 |

## 공통 규칙

1. 재현 조건(환경, 버전, 전제)을 상단 또는 전제 절에.
2. 코드 스니펫 **한 블록 ≤20줄**, 한 가지 포인트만.
3. **before → after**가 있으면 둘 다. after만 있으면 불완전.
4. 비범위(다루지 않는 것) 명시.
5. 수치/로그는 출처 또는 `[TODO-FACT]`.
6. 마케팅 CTA 금지. 다음 행동 = 검증/롤백/관련 문서 링크.

## 아웃라인 골격 (BUG 예)

```
## 범위 / 비범위
## 증상과 재현
## 원인
## 수정 (before / after)
## 검증, 롤백
## 다음에 읽을 글
```

## 아웃라인 골격 (MIG 예)

```
## 왜 옮기는가
## before 상태
## after 상태
## 단계 체크리스트
## 롤백
## 남은 빚
```
